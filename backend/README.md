# Пульс: сервер

FastAPI, SQLite в режиме WAL, серверная предмодерация, профили, подписки, друзья, обсуждения и личные чаты. Нейросетевая модерация в эту версию не включена.

## Запуск из корня проекта

Нужен Python 3.11–3.15. Разработка и проверка выполняются на Python 3.13.

```powershell
python -m venv backend/.venv
backend/.venv/Scripts/python.exe -m pip install -r backend/requirements.txt
backend/.venv/Scripts/python.exe -m uvicorn backend.main:app --host 0.0.0.0 --port 8000
```

Если создание окружения завершается ошибкой на `ensurepip`, но Python в `.venv` уже создан:

```powershell
python -m pip --python backend/.venv/Scripts/python.exe install -r backend/requirements.txt
```

Проверка сервера: `http://localhost:8000/api/health`. Интерактивная спецификация всех маршрутов: `http://localhost:8000/docs`. Для телефона в той же сети используйте IPv4 компьютера, порт `8000`; для стандартного Android Emulator — `10.0.2.2:8000`.

Для установки передайте на телефон сам файл `artifacts/pulse-uunit-arm64.apk` (для OnePlus 15 и большинства современных Android-смартфонов) либо универсальный `artifacts/pulse-uunit.apk`, затем откройте APK на телефоне. Сервер обслуживает API приложения; файлы сборки по HTTP не публикуются.

`--host 0.0.0.0` открывает сервер в локальной сети. Для внешнего развёртывания нужны HTTPS через обратный прокси и собственные аккаунты вместо публичных демонстрационных паролей.

## Демонстрационные данные

При первом запуске автоматически создаются 16 опубликованных материалов, 2 авторские заготовки, обсуждения, реакции, подписки и дружеские связи. Счётчики считаются из настоящих строк базы. Даты мероприятий привязаны к дню первого запуска, часовому поясу Уфы (UTC+5).

**Аккаунты, публикации и мероприятия вымышлены. Приложение не является официальным сервисом УУНИТ.** Это также указано в `/api/health` (`demo_notice`). Фотографии в `media/covers/` иллюстративные; сведения о происхождении находятся в документации проекта.

| Роль | Почта | Пароль |
|---|---|---|
| Студент | `student@pulse.local` | `Student123!` |
| Модератор | `moderator@pulse.local` | `Moderator123!` |

Пользователь `student` дружит с Тимуром и Артёмом; Дарья отправила ему заявку. В ленте друзей видны предстоящие события, на которые собираются принятые друзья. Подписка на автора и взаимная дружба — отдельные связи.

База по умолчанию: `backend/data/pulse.sqlite3`. Загруженные изображения: `backend/data/uploads/`. Данные сохраняются между перезапусками, сидирование не дублирует содержимое. Для полностью нового набора данных укажите другой путь `PULSE_DB` перед запуском. Не удаляйте рабочую базу, чтобы обновить оформление или перезапустить сервер.

## Настройка

Переменные окружения читаются при старте приложения:

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `PULSE_DB` | `backend/data/pulse.sqlite3` | Путь к SQLite |
| `PULSE_UPLOAD_DIR` | `backend/data/uploads` | Папка изображений |
| `PULSE_SEED_DEMO` | `true` | `false` создаёт только категории, без публичных аккаунтов и вымышленных публикаций |
| `PULSE_CORS_ORIGINS` | localhost:5173, localhost:3000, localhost:8080, 127.0.0.1:5173 | Точные разрешённые origin через запятую |
| `PULSE_PUBLIC_BASE_URL` | пусто | Внешний адрес сервера для абсолютных URL загрузок |

Установка `PULSE_SEED_DEMO=false` не удаляет уже созданные данные. При чистом запуске без демоданных для назначения модератора владелец сервера должен явно изменить роль нужного пользователя в БД. Регистрация и редактирование профиля не позволяют самому выдать себе роль.

## Контракт API

Все маршруты данных начинаются с `/api`. Защищённые запросы используют `Authorization: Bearer <token>`. Вход и регистрация возвращают `{token,token_type,expires_at,user}`. Сессия действует 14 дней; выход отзывает конкретный токен. В БД хранятся PBKDF2-SHA256 хеши паролей с солью и 600 000 итерациями, а также SHA256 хеши случайных токенов. После 30 попыток входа или регистрации с одного адреса за 15 минут сервер возвращает `429`.

Списки обычно имеют вид `{items,total,page,page_size}`. Страницы начинаются с 1, максимальный размер основной ленты — 100. Категории (`GET /categories`) возвращаются массивом `{id,name,color}`; в публикации `category` — такой же объект, при создании/редактировании передаётся строковый `id`.

`GET /posts` поддерживает `category`, `search` (включая русский регистр), `type=news|event`, `period=today|week`, `saved=true`, `free=true`, `feed=following|interests|for_you|friends`. `week` — следующие 7 календарных дней по Уфе, включая сегодняшний. Персональные фильтры требуют входа. Лента друзей включает только предстоящие опубликованные мероприятия с участием принятых друзей и сортирует по числу таких друзей, затем по времени начала. `friend_attendees` раскрывает только имена принятых друзей текущего пользователя; личности прочих участников не выдаются.

Создание публикации: `POST /posts`; `submit=false` сохраняет черновик, по умолчанию публикация отправляется в очередь. `PATCH /posts/{id}` доступен только автору. Изменение опубликованного материала снимает его с общей ленты до новой проверки. Неопубликованные материалы видят только автор и модераторы; общая лента, поиск, сохранённое и публичный профиль их не показывают.

Модерация:

- `GET /moderation/posts?status=pending` — очередь.
- `POST /moderation/posts/{id}/decision` — `{decision:"publish"|"changes_requested"|"reject",expected_updated_at:"точная строка updated_at проверенной версии",reason?:"..."}`. При возврате/отказе причина обязательна. Изменённая или уже обработанная версия даёт `409`. Собственную публикацию модератор одобрить не может.
- `GET /moderation/posts/{id}/history` — история, доступная автору и модератору. Каждая запись содержит `decision`, совместимый `action`, `actor`/`moderator`, `reason`, `created_at`.
- `POST /posts/{id}/submit` — повторная отправка после исправления.

Социальные функции:

- `PUT/DELETE /users/{id}/follow` — подписка; `GET /friends` и `GET /friends/requests` — друзья и заявки.
- `PUT /users/{id}/friend-request`, `POST /users/{id}/friend-request/accept`, `DELETE /users/{id}/friendship` — отправить, принять входящую, отменить/отклонить/удалить дружбу. Дублирование заявки не создаёт друзей автоматически.
- `PUT/DELETE /posts/{id}/bookmark`, `/reaction`, `/attendance`. Реакция передаётся как `{reaction:"like"|"fire"|"heart"|"clap"}`. У пользователя одна реакция на публикацию; повторные PUT не увеличивают счётчики.
- `GET/POST /posts/{id}/comments`; новый комментарий `{body,parent_id?}`. Ответ может ссылаться только на комментарий в том же обсуждении. `DELETE /comments/{id}` доступен автору или модератору; удаление ветки удаляет ответы.
- `POST /comments/{id}/report {reason}`; модератор читает `GET /moderation/reports`, удаляет нарушающий комментарий либо закрывает жалобу через `POST /moderation/reports/{id}/resolve`.
- `GET /notifications` и `PUT /notifications/read` — сообщения о проверках, комментариях и заявках в друзья. Собственные уведомления доступны только владельцу.
- `GET/POST /chats`, `GET/POST /chats/{id}/messages`, `PUT /chats/{id}/read` — личная переписка. Новая переписка и отправка сообщений доступны принятым друзьям; старую историю можно прочитать после удаления дружбы. Сообщение содержит `{body?,image_url?}`, хотя бы одно поле должно быть непустым. История поддерживает `before_id`/`after_id` и `page_size` до 100; `has_more` относится к выбранному направлению.
- `POST /chats/{id}/images` — приватное фото (`multipart/form-data`, поле `file`), возвращает `{url}` для последующей отправки в сообщении. `GET /chats/{id}/images/{filename}` требует токен участника переписки и выдаётся с `Cache-Control: private, no-store`. Другой пользователь получает `404`; фото нельзя прикрепить к другой переписке.

`POST /uploads` принимает `multipart/form-data` с полем `file`, проверяет реальные JPEG/PNG/WebP, ограничивает файл 8 МБ и 30 млн пикселей. Сервер исправляет ориентацию снимка, перекодирует его в JPEG без метаданных с длинной стороной до 2400 пикселей и выдаёт случайное имя. Этот маршрут используется для публикаций и аватаров: его изображения доступны публично. Фотографии личных сообщений используют отдельный защищённый маршрут; по умолчанию они сохраняются в `backend/data/chat_uploads/`.

Ошибки возвращаются как `{detail:"понятная причина"}`. Ошибки валидации также содержат `errors:[{field,message}]`. Почта пользователя не выдаётся другим участникам. HTML в текстах не интерпретируется сервером; клиент должен отображать пользовательский текст как текст.

`PATCH /me` поддерживает имя, `handle` (3–30 латинских букв, цифр, точек или подчёркиваний), факультет, курс, описание, интересы, URL аватара и `avatar_color` (`#RRGGBB`). Имя пользователя приводится к нижнему регистру и проверяется на уникальность; занятое имя возвращает `409`. Поле роли недоступно для изменения.

## Проверка

```powershell
backend/.venv/Scripts/python.exe -m pytest backend/tests -q --basetemp backend/.test-tmp
```

Тесты создают изолированные SQLite и папки загрузок. 20 интеграционных тестов проверяют права доступа, полный цикл модерации и защиту от устаревшего решения, приватность неопубликованных материалов и событий друзей, принятие заявок, редактирование профиля, счётчики, обсуждения/жалобы, сессии и выход, ограничения попыток входа, фильтры, пагинацию, загрузку/ориентацию настоящего изображения, повторный запуск сида, личные сообщения и приватные фотографии. Проверено на всех версиях из `requirements.txt`.

Это работающий хакатонный прототип. В нём пока нет восстановления пароля по почте, подтверждения университетского аккаунта, push-уведомлений и распределённого хранения файлов. Лента и личные сообщения обновляются клиентом запросами; для большой аудитории понадобится отдельное развёртывание и дальнейшая эксплуатационная настройка.
